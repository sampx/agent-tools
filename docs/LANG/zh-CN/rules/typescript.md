# TypeScript 开发规范

## 代码风格

- 格式化由项目 prettier 配置负责,风格值(引号、分号、缩进、行宽)以项目配置为准,不写死
- 不使用 ESLint/Prettier 以外的风格强制工具,避免规则与工具配置冲突

## 命名约定

- 变量和函数:camelCase
- 类和接口:PascalCase
- 常量:UPPER_SNAKE_CASE
- 私有成员:#privateField 或 _privateField

## 类型定义

- 为所有函数参数和返回值指定类型
- 使用接口定义对象类型
- 使用类型别名处理复杂类型
- 优先使用 `interface` 而非 `type`,除非需要联合类型或映射类型

## 模块导入

- 使用 ES6 import/export
- 按顺序分组:Node.js 内置, 第三方库, 本地模块
- 使用命名导入而非默认导入

## 异步操作

- 使用 async/await 而非 Promise 链
- 正确处理错误(try/catch)
- 避免使用 `any` 类型

## 代码组织

- 每个文件只导出一个主要功能
- 相关功能放在同一目录
- 使用 index.ts 导出公共 API

## 测试验证机制

测试基础设施的建立遵循以下通用原则,适用于任何 vitest 项目。

### 分层模型

采用测试金字塔,三层职责由**依赖边界**决定,而非由功能模块划分:

| 层 | 依赖边界 | 特征 |
|----|---------|------|
| Unit | 全部依赖可 mock;无网络、无数据库、无文件系统 | 毫秒级、完全并行、覆盖绝大多数行为 |
| Integration | 本地实现真实(如真实 git)、外部边界 mock(localhost HTTP) | 秒级、限于临时目录、验证多模块协作 |
| E2E | 真实外部系统(真实 API、真实 CLI、真实凭证) | 分钟级、独立运行、少而精 |

比例与分工:Unit 为主(约 70%),Integration 次之(约 25%),E2E 最少(约 5%),是第二道防线,不追求覆盖所有命令。

归属判定准则:能用 mock 验证的不上集成,能用本地实现验证的不上 E2E。只有"外部系统侧语义无法本地模拟"的行为才进 E2E 层。

高层测试失败说明两层问题——功能 bug 与缺失的单元测试。修复前先补对应单元测试复现,再修复。

### 隔离原则

所有层的测试必须高隔离、可任意顺序、可并行:

- 每个测试独立创建和清理自己的资源(beforeEach/afterEach 成对管理),不依赖其他测试留下的数据
- 临时目录、mock 服务、环境变量必须成对创建与恢复
- 禁止测试间共享可变状态

各层隔离手段:Unit 用进程级 mock 替换依赖模块;Integration 用真实本地实现(如 `git init` 构造临时仓库)+ mock 外部边界(localhost HTTP)+ 临时目录;E2E 用隔离的运行环境 + 持久测试资产只读复用 + 账号动态获取。

### 存放规则

测试文件组织由三个正交维度决定:

- **位置**(放哪):由被测源码结构决定,镜像源码路径;跨模块链路按功能域归类
- **分层**(怎么表达):文件名后缀,不建分层子目录
- **筛选**(怎么运行):测试框架的标签机制,不参与命名与存放

命名约定:

| 层 | 命名 | 位置 |
|----|------|------|
| Unit | `<模块>.test.ts` | 镜像被测源码 |
| Integration(单模块) | `<模块>.integration.test.ts` | 镜像被测源码 |
| Integration(跨模块链路) | `<链路>.test.ts` | 独立集成目录,按功能域归类 |
| E2E | `<场景>.e2e.test.ts` | 独立 E2E 目录 |

同一被测源码的单元与集成测试必须分文件,因两者的依赖边界不同(单元要 mock 一切,集成要真实本地实现),混文件导致 setup 互相干扰。不按层级建子目录(unit/ 与 integration/ 目录分层是过度设计,破坏源码对齐)。

### 框架选型

- vitest 是默认选择,默认配置通配 `tests/**/*.test.ts`
- 分层筛选用 vitest Test Tags(`--tags-filter`),在配置中声明各层标签
- E2E 用独立配置(长超时 + 只包含 E2E 目录),保证不进默认套件
- E2E 用测试框架原生能力实现,不造 shell 脚本轮子:框架原生支持长超时、标签筛选、结构化断言、失败差异输出、共享 helper——shell 手写的通过/失败计数与文本匹配是这些能力的低配复刻

### 运行门控

| 时机 | 运行范围 |
|------|---------|
| 编码中(高频) | 仅当前模块的 Unit |
| 提交前(中频) | 全部 Unit + Integration |
| 发布前(低频) | 全部含 E2E |

CI 门控:Unit + Integration 阻塞合并(快速、稳定、无外部依赖);E2E 不阻塞合并(依赖真实凭证与网络,PR 级不稳定),改为手动触发或定时运行。

### 外部系统测试资产

涉及真实外部系统的 E2E,资产策略遵循两条原则:

- 持久资产只读复用,不创建不清理:外部系统的状态(账号、仓库、网络关系)不可重建,删除后无法恢复相同拓扑
- 运行结束零残留:临时产物(目录、分支、数据)必须在测试结束时清理;不依赖一次性临时资源(如按凭证限定的临时资源),因凭证随资源删除而失效

### 存量迁移

既有测试欠债(散落文件、无分层标注)按"触碰即迁移"原则处理:仅在修改某测试或其对应源码时,顺手迁移到目标位置并补后缀。不发起大规模重构,避免污染历史、增加审查负担。
